# webby

A web browser with a Flutter UI and [Ladybird](https://ladybird.org)'s engine underneath: **LibWeb** renders pages
and **LibJS** runs their JavaScript.

```
Flutter (Dart)  ──dart:ffi──▶  libwebby.so  ──LibWebView──▶  WebContent process (LibWeb + LibJS)
  URL bar, back/forward,        C ABI over a                  RequestServer (networking)
  page image, input             headless ViewImplementation   ImageDecoder
```

Ladybird already runs each page in a sandboxed `WebContent` helper process and talks to it through `LibWebView`.
Webby adds a new Ladybird "UI frontend" (`native/`, built as `UI/Flutter` inside the Ladybird tree) whose
`ladybird` target is a shared library, `libwebby.so`, instead of the Qt app. It exposes a small C API
(`native/webby_ffi.h`): create a view, load a URL, back/forward/reload/stop, resize, mouse/wheel/key input, and
read the latest frame as BGRA pixels plus the page's URL, title, loading state and cursor.

The Flutter app (`app/`) pumps Ladybird's event loop from the Dart thread, turns each new frame into a `ui.Image`,
and forwards pointer and keyboard events.

## Quick start (pixi)

With [pixi](https://pixi.sh) installed, one command fetches everything and runs the browser:

```sh
pixi run start                          # or: pixi run start -a https://example.com
```

The first run downloads Flutter 3.35.5 and the prebuilt Ladybird runtime below (sha256-checked) into `third_party/`,
installs the Linux build toolchain (clang, lld, CMake, ninja, GTK 3…) from conda-forge into `.pixi/`, and then runs
`scripts/run_app.sh`. Later runs skip the downloads. Set `WEBBY_LADYBIRD_PREFIX` to use your own Ladybird build
instead of the prebuilt. Flutter isn't packaged on conda-forge, so it comes from Google's release tarball.

## Layout

| Path | What |
| --- | --- |
| `native/` | C++ shim: `Webby::Application`, `Webby::View` (a `HeadlessWebView` that copies presented frames) and the C ABI |
| `patches/` | One small patch to Ladybird's `UI/CMakeLists.txt` adding the `LADYBIRD_UI_FLUTTER` option |
| `LADYBIRD_COMMIT` | The Ladybird commit this is built against |
| `scripts/build_ladybird.sh` | Clones Ladybird, applies the patch, links `native/` in, builds `libwebby.so` and the helper processes |
| `scripts/run_app.sh` | Runs the app against the Ladybird build |
| `pixi.toml`, `scripts/pixi_*.sh` | `pixi run start`: fetches Flutter + the prebuilt runtime, builds and runs the app with a conda-forge toolchain |
| `scripts/modal_build.sh` | The same build in a fresh Ubuntu 24.04 Modal sandbox (caches on a volume at `/build`) |
| `app/` | The Flutter app (`lib/`); the Linux runner is generated by `flutter create` |

## Prebuilt runtime (Linux x86_64)

To skip the Ladybird build, download the prebuilt runtime from the package registry: `libwebby.so`, the Ladybird and
vcpkg libraries, the helper processes (`libexec/WebContent`, `RequestServer`, …) and `share/Lagom`. It was built on
Ubuntu 26.04 and needs glibc 2.43 or newer; RPATHs are relative, so the folder can live anywhere.

```sh
P=https://gitlab.latha.org/api/v4/projects/4/packages/generic/webby-prebuilt/2026.10.10
curl -fLO $P/webby-prebuilt-linux-x64.tar.zst -fLO $P/webby-prebuilt-linux-x64.tar.zst.sha256
sha256sum -c webby-prebuilt-linux-x64.tar.zst.sha256
tar --zstd -xf webby-prebuilt-linux-x64.tar.zst
WEBBY_LADYBIRD_PREFIX=$PWD/webby-prebuilt scripts/run_app.sh -a https://example.com
```

## Building (Linux)

Ladybird's own [build prerequisites](https://github.com/LadybirdBrowser/ladybird/blob/master/Documentation/BuildInstructionsLadybird.md)
apply (clang ≥ 19 or gcc ≥ 14, CMake ≥ 3.30, Rust, ninja, nasm, autoconf…), minus Qt. Then:

```sh
scripts/build_ladybird.sh   # first run builds vcpkg deps (Skia, ICU, ANGLE, ffmpeg…) and takes a while
scripts/run_app.sh          # generates app/linux with `flutter create` if needed, then `flutter run -d linux`
```

Pass a URL to open it on start: `scripts/run_app.sh -a https://example.com`.

`WEBBY_LADYBIRD_PREFIX` points at a Ladybird prefix containing `lib/libwebby.so`, `libexec/WebContent` (and the
other helpers) and `share/Lagom`. Without it, the app looks in `<app bundle>/lib/ladybird`.

## Status

Minimal vertical slice: one tab, URL/search bar, back/forward/reload/stop, mouse, wheel and keyboard input, link
hover status, cursors, HiDPI. Frames are copied through the CPU (Ladybird's CPU painting mode) and uploaded
with `decodeImageFromPixels`; a Flutter texture would be the next step for speed.
